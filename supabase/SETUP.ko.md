# 새 Supabase 프로젝트 연결

0.2.1 기본 서버를 사용하는 일반 사용자는 이 절차 없이 프로그램에서 회원가입하면 됩니다. 아래는 별도 서버를 운영할 프로젝트 소유자의 설정입니다. Supabase 관리 계정의 로그인 비밀번호나 DB 비밀번호, 관리자 키는 프로그램 또는 채팅에 입력하지 않습니다.

1. https://supabase.com/dashboard/new 에서 본인 계정으로 로그인합니다. 조직을 선택하고 Free 플랜에서 `JYTODO` 프로젝트를 만듭니다. DB 비밀번호는 이 화면에서 직접 생성·보관합니다.
2. 생성이 끝나면 **SQL Editor → New query**에서 이 폴더의 [schema.sql](schema.sql) 전체를 붙여 넣고 Run을 누릅니다. RLS를 끄거나 테이블 접근을 모두 허용하는 정책을 추가하지 않습니다.
3. **Authentication → Providers → Email**에서 이메일 로그인을 사용합니다. 이메일 인증은 켜 둡니다. **URL Configuration**의 Site URL 및 Redirect URLs에는 `http://127.0.0.1:43127/auth/confirmed`를 등록합니다. Google 캘린더의 OAuth 리디렉션과 다른 주소입니다.
4. 프로젝트의 **Settings / Connect / API**에서 **Project URL**과 **Publishable key**를 확인합니다. 기존 프로젝트의 `anon` 키도 지원합니다. `service_role` 또는 `sb_secret_` 키는 절대로 배포하지 않습니다.
5. 프로그램을 실행해 **동기화 공간 준비** 화면에 URL과 공개 키를 입력합니다. 프로그램에서 회원가입하고 이메일을 확인한 후 로그인합니다. 메일을 확인할 때 프로그램을 실행해 두고, 기본 브라우저의 안내가 보이면 프로그램으로 돌아옵니다.
6. 다른 PC에서도 같은 프로젝트에 연결하고 같은 이메일·비밀번호로 로그인합니다. 기본 약 10초 간격으로 동기화하며 화면에서 지금 동기화를 누를 수 있습니다.

프로젝트 연결 정보를 배포 파일에 미리 넣으려면 저장소의 `cloud-config.json`에 URL·공개 키만 입력해 새 버전을 빌드합니다. 그러면 새 PC에서는 프로젝트 설정 없이 사용자 로그인만 하면 됩니다. 공개 키가 보여도 RLS가 본인 계정의 데이터만 허용합니다. 실제 관리자 키로 이 제한을 우회해서 사용하지 마세요.

연결 뒤 로그인은 되는데 동기화 오류가 나면 SQL 실행 성공 여부와 프로젝트 URL/키의 짝을 확인합니다. 이메일이 오지 않으면 Supabase 발송 한도·메일 제공자 설정·스팸함을 확인합니다. 기본 메일 서비스는 프로젝트 팀 외의 사용자 발송을 제한할 수 있으므로 공개 배포에는 별도 SMTP가 필요할 수 있습니다.

현재 기본 JYTODO 프로젝트는 연결되어 있고 계정별 RLS 및 Auth 리디렉션 설정이 적용되어 있습니다. 직접 선택한 다른 프로젝트를 사용할 때에는 이 문서의 SQL·Auth 설정이 선행되어야 합니다.
